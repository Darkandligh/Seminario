# Reporte de defecto

**Id:** D-01
**Título:** `registrar_comanda` acepta más de 50 platos si se reparten en varias filas
**Reportado por:** Eduardo Ascencio · **Fecha:** 2026-11-26

## Pasos para reproducir

1. Clonar el repositorio y pasar a la rama `semana-6` en el commit `69f0f40`, antes de la corrección.
2. Instalar las dependencias: `pip install -r requirements.txt`.
3. En Python, registrar una comanda para la mesa 4 con 3 filas de «Chop suey» (arroz frito, pollo, personal, medio) y cantidad 20 en cada una.

## Resultado esperado

La comanda se rechaza con `ComandaInvalida`: «Una comanda tiene máximo 50 platos». El tope de 50 platos por comanda viene de H-03 en `revision_seguridad.md`, para que una sola petición no llene la pantalla de cocina.

## Resultado obtenido

La comanda se registra en estado «recibido» con 60 platos. Con 50 filas de cantidad 20 entran 1000 platos.

## Entorno

Python 3.13, Linux, rama `semana-6`, commit `69f0f40`.

## Evidencia

La prueba `test_mas_de_50_unidades_en_total_se_rechaza` en `tests/test_abuso_comandas.py`, que falló en el commit `3556eef`: `1 failed, 38 passed`.

## Clasificación

**Severidad:** Media — deja sin efecto el tope que protege la pantalla de cocina y la memoria del mini PC, pero hace falta mandar los datos a propósito.
**Prioridad:** Media — el tope existe para la hora pico, cuando un pedido así sí haría daño.

## Análisis

**Caso mínimo:** `registrar_comanda(4, [{"plato": "Chop suey", "base": "arroz frito", "proteina": "pollo", "tamano": "personal", "picante": "medio", "cantidad": 20}] * 3)`
**Causa:** `afenix/comandas.py` comparaba `len(items)` con `MAX_PLATOS`, es decir, contaba filas y no platos.
